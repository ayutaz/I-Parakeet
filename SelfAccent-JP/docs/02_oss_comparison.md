# 02. 既存 OSS との差分

## 1. 問題設定

日本語 TTS で「読み」と「アクセント」を利用者が直せるかどうかは、モデルの入力形式で大きく変わる。

| 入力形式 | 代表 | 読み・アクセントの直し方 | 弱点 |
|---|---|---|---|
| 音素＋アクセント記号（G2P 前段あり） | VOICEVOX、Style-BERT-VITS2、piper-plus、ESPnet / ttslearn の日本語レシピ、Matcha-TTS の日本語化 | G2P の出力（pyopenjtalk のアクセント句・アクセント核）を直接編集する。GUI やユーザー辞書もある | 前段の G2P に依存する。多言語化しにくい。G2P の誤りがそのまま出る |
| raw text（G2P なし） | CosyVoice2/3、Sarashina2.2-TTS、Fish-Speech、Qwen-TTS 系、F5-TTS の日本語化、CuteTTS 系 | **基本的にできない**。カナに書き換えるのが限界で、アクセントは指定できない | 珍しい語・固有名詞を誤読する。カナにしてもアクセントは運任せ（論文の値ではカナの正解率 0.38〜0.60） |

近年の多言語・大規模モデルは後者の raw text 入力が主流で、日本語の読み・アクセント制御が抜け落ちている。

## 2. 直接の比較対象

| | **UtterTune**（2508.09767, OSS） | **自己蒸留**（2609.17234, 本実装） | ユーザー辞書（VOICEVOX 等） | カナ書き換え |
|---|---|---|---|---|
| 対象モデル | CosyVoice2（raw text） | raw text の任意の骨格（論文では 4 種） | 音素入力モデル | raw text モデル |
| 入力記法 | `<PHON_START>カナ'<PHON_END>` | 同じ記法 | 読み＋アクセント型 | カナ |
| 学習するもの | LoRA（q,k,v,o）＋新しいトークンの埋め込み | 同じ | なし | なし |
| **学習データ** | **録音付きコーパス**（JSUT/JVS の 15k 文。転写の一部をタグに置き換える） | **骨格自身の出力だけ（録音不要）** | — | — |
| 話者・声質の維持 | 学習コーパスの話者に引っ張られうる | 教師が骨格自身なので、骨格の声と韻律をそのまま保つ | — | — |
| ライセンス上の制約 | 録音コーパスのライセンスを受け継ぐ（公開 LoRA は非商用） | 骨格のライセンスだけ | — | — |
| 未知語のアクセント | 0.8 前後（UtterTune 論文） | 0.80〜0.93（論文） | 辞書次第 | 0.38〜0.60 |
| 公開コード | ✅ | ❌（**本リポジトリが初の実装**） | ✅ | — |

### 自己蒸留が UtterTune に加えるもの

1. **録音が要らない**: 教師は骨格自身なので、テキストさえあれば学習データを無限に作れる。対象話者の録音も、アクセント付きの音声コーパスも不要。
2. **骨格の声質を壊さない**: 録音コーパスへ fine-tune すると、骨格の声質や韻律がコーパス側へ寄りうる。自己蒸留では目標が骨格自身の出力なので、変わるのはタグの読み方だけになる。
3. **骨格を選ばない**: 必要なのは「骨格で生成する」と「骨格自身の損失を計算する」の 2 つだけ。自己回帰の codec LM、拡散、エンコーダ-デコーダのいずれにも適用できる。

## 3. 本リポジトリ（SelfAccent-JP）の位置づけ

| 要素 | 既存の OSS | 本リポジトリ |
|---|---|---|
| タグ記法の解析・生成・検証（モーラ分割、アクセント核、句境界、東京式の高低） | UtterTune には文字列処理しかない | `selfaccent.tags`（テスト付き） |
| 自己蒸留ペアの採掘（一般語の判定、複合語の先頭語の除外、恒等ペア） | なし | `selfaccent.mining` |
| 骨格に依存しない蒸留ループと adapter 形式（LoRA ＋ 新しい行の埋め込み、骨格の語彙とのハッシュ照合） | UtterTune は CosyVoice2 専用 | `selfaccent.distill`、`selfaccent.backbones.base.Backbone` |
| 任意の読み・アクセントの参照音声（オラクル） | なし | `selfaccent.frontend.OracleRenderer`（pyopenjtalk の NJD を書き換えて HTS で合成） |
| アクセントの自動判定（聴取試験の代用） | なし（UtterTune は CER・UTMOS・主観評価） | `selfaccent.metrics` / `selfaccent.benchmark`（F0 の強制選択。判定器自体の精度も検証する） |
| CPU で全工程を検証できる骨格 | なし | `TinyMatcha`（raw text 入力の CFM-TTS、5M パラメータ） |

### 関連する自作 OSS との接続

- **LatticeG2P-JP**（2609.19805 の再実装）: 未知語の読みを推定する。推定結果をそのままタグにできる（`scripts/infer.py --tag 語=ヨミ'`）。
- **piper-plus / sanoTTS-jp**: 音素入力なので本手法は不要。raw text 骨格（**CuteTTS-jp**、**uZipVoice** など）に適用するのが本手法の想定。

## 4. 本リポジトリがまだ扱っていないもの

- 実在の事前学習済み骨格（CosyVoice2、Sarashina2.2-TTS など）への適用。この環境では Hugging Face / ModelScope に接続できなかった。移植の手順は [03_architecture.md §4](03_architecture.md) に書いた。
- 論文の主観評価（スクリーニングした評定者による聴取試験）。自動判定で代用し、手順は [04_benchmark.md](04_benchmark.md) にある。
