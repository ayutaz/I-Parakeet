## 3. 選定: arXiv 2609.17234

**"Self-Distilled Pronunciation and Accent Control for Neural TTS"**（Shuhei Kato、2026 年 9 月中旬）

### 3.1 論文の主張（アブストラクト・検索要約から）

1. raw text を直接読む end-to-end TTS（CosyVoice2、Sarashina2.2-TTS など）は語彙辞書を持たないので、珍しい語・固有名詞・専門用語の読みを推測で済ませてしまう。日本語の母語話者は、読みと**ピッチアクセント**の両方が合っていないと正しいと感じない。
2. 解決策は自己蒸留。凍結した骨格モデルが正しく読める**一般的な語**を含む文を読ませ、その出力を教師にする。同じ文で語を「**注釈付きの読み＋ピッチアクセント**」に置き換えたものを生徒の入力にする。**新しい録音は不要**。
3. Sarashina2.2-TTS では、未知の語でも指定どおりのアクセントに聞こえた割合が 0.89 だった（スクリーニングした評定者、Fleiss κ = 0.85）。プレーンなカナでは 0.57。
4. 4 種の骨格（自己回帰・拡散・エンコーダ-デコーダ）で、難読語の正解率は 0.80〜0.93。カナだけでは 0.38〜0.60。

### 3.2 選んだ理由

- **日本語での価値が最も直接的**。LLM 系 TTS は日本語の漢字の読みを誤りやすいが、読み・アクセントを録音なしで後から修正できる。ユーザー辞書の機能そのものになる。ayutaz/LatticeG2P-JP などの G2P で読み・アクセントを推定すれば、そのままタグとして渡せるので、G2P と TTS をつなぐ部品として相性がよい。
- **コードが見つからない**。著者の GitHub には前身の UtterTune しかない。
- **中核が骨格に依存しない**。教師の生成、ペアの採掘、タグ埋め込みと LoRA の学習という 3 段構成で、骨格固有なのは「損失」と「出力の型」だけ。CPU で動く小型骨格で全工程を検証し、実骨格（CosyVoice2 など）へはインタフェースの差し替えで移せる。
- **自動評価を組める**。OpenJTalk の HTS 音声を「オラクル」にすると、任意の読み・任意のアクセント型の参照音声を作れる。論文の聴取試験を、強制選択による自動判定で代用できる。
